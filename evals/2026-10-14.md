## Policy dry runs

These used actual Claude inference but **no tools**. They establish response behavior, not rendered UI quality, concurrent execution, or enforcement:

- New UI: stopped at Gate 0 without an implementation plan or production code; required manual rendered review when a browser is unavailable.
- Mocked-only UI checks: kept persistence acceptance unverified; requested the real integrated journey.
- Shared router ownership: after the correction below, the Queen assigned one owner without an unnecessary user approval gate.
- Explicit user model selection: respected the user's Sonnet choice over the Queen's Opus preference; no dispatch was claimed in this dry run.
- Release boundary: passing features did not grant deployment authority.

## Findings fixed

1. **Permission-denial scope:** an initial compound command included unallowlisted operations. Claude incorrectly generalized that denial to “no shell” and skipped permitted tests. The skill now distinguishes command-level denial from unavailable capability and directs agents to use a narrower explicitly permitted operation without bypassing restrictions. The later stale-state run encountered another compound denial and recovered with permitted individual commands.
2. **Manual-state schema drift:** the fallback created `{"features": [...]}`, nested budgets, omitted default roles and used `criteria` instead of `criterion`. The state reference now gives the exact canonical configuration and array/evidence shape. `scripts/validate_hive.py` detects malformed state before resume and never writes to it. A fresh Claude session preserved originals and all meaning while correcting the observed drift; validation then passed.
3. **Mockup placement ambiguity:** one policy response described an external mockup but suggested `hive/mockups/`. The skill now explicitly excludes the project hive/source folders. The repeated Opus scenario selected an external sibling directory.
4. **Unnecessary ownership approval:** the first policy response asked the user to confirm routine router ownership. The skill now explicitly assigns routine coordination to the Queen. The repeat resolved ownership without a new approval gate.
5. **Validator robustness:** independent review found that deeply nested JSON escaped with a traceback and duplicate keys silently selected the last value. The parser now rejects duplicate keys and nonstandard JSON constants, catches excessive nesting, returns exit 2, and preserves inputs. Regression tests and independent rechecks passed.

## Remaining limits

This is a bounded two-harness validation, not a certification of every harness or production workload. Native Codex discovery, Cursor/Copilot/Gemini integrations, automatic skill triggering, large parallel builds, rendered-user design approval, complete UI delivery, deployment, and comparative model cost/quality are untested. Manual explicit-file usage is the portable baseline. The validator checks structure, not whether an approval, test result or independent-review claim is true. No model instructions substitute for host permission enforcement.
